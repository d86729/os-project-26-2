# 대형 그래프 생성과 실행 시간 점검

`protocol.json`에 시드와 크기를 고정한 뒤 generation-v1으로 기지 64·128·256·512·1024개마다 두 그래프를 만들었다. 두 예산을 적용한 **10개 그래프·20사례**의 번들, 표준 입력, SHA-256 및 생성 시간을 보관한다. n=18 시드는 난수 추출 순서에 포함된 예비 값이며 이번 실행에 사용하지 않았다.

두 기존 구조 기준선의 출력 40회는 모두 형식·예산 검사를 통과했다. n=1024에서 제출 프로그램의 최대 시간은 매개중심성 8.73초, 차수 0.073초였다. 이 값은 하나의 CPU 코어, 벽시계 300초, 프로세스 주소 공간 6GB를 적용한 **로컬 제출 실행 시간**이다. 웹의 cgroup·bubblewrap 실행이 아니며 출력 생성 후의 공식 점수 계산을 포함하지 않는다. 300초는 상한이므로 일찍 반환한 방법이 300초를 소모하지 않는다.

공식 평가를 별도로 시험하기 위해 각 크기의 첫 시드·20% 예산에서 차수 방호안을 대상으로 20초 진단을 사용했다. 기지 64개는 약 1.32초, 128개는 약 13.24초에 점수를 계산했다. 256개는 20초 진단 한도를 넘겨 중단했고, 512개와 1024개는 미실행이다. 이 진단 한도는 웹의 공식 평가 시간 제한을 뜻하지 않는다. `scoring-pilot.jsonl`에 성공·중단·미실행 상태를 보존한다.

별도의 n=16 시드 두 개를 대상으로 예산별 20초 인증 완전탐색 시범을 했다. 네 조건 모두 미완료다. 40% 예산의 경우 가능한 집합 약 9,100만~9,290만 개 가운데 첫 20초 동안 약 9,858~43,074개를 평가했다. 초기 처리 속도와 캐시 상태가 달라질 수 있어 이 시범만으로 3시간 내 완료 가능성을 확정할 수 없다. 장시간 확정 실행은 팀원의 웹 채점과 공용 잠금을 공유하므로 무작정 반복하지 않았다. `exact-pilot.jsonl`에 원기록이 있다.

모든 대형 번들은 정확 참조가 없으며 공개 문제은행에 추가되지 않았다. 공개하려면 같은 그래프의 두 예산 모두 현행 3시간 이내 완전탐색, 유리수 인증과 재채점이 필요하다. 이번 생성기는 여전히 하나의 희소 그래프 계열이므로 실제 통신망 구조 전체의 다양성을 대표하지 않는다. 이 20사례는 이전 발표의 20사례와 별도의 시간 점검이며 전략 간 공식 점수 비교로 보고하지 않는다.

- `bundles/`: 참조 없는 연구용 예산별 문제
- `inputs/`: 공통 입력 계약을 적용한 표준 입력
- `preparation.jsonl`, `runs.jsonl`: 준비와 제출 출력의 실측 원자료
- `scoring-pilot.jsonl`, `exact-pilot.jsonl`: 공식 평가와 인증 탐색의 별도 진단
- `summary.json`: 집계 및 측정 환경의 한계
- `exact-manifest.json`: n=16 두 시드와 두 예산의 정식 인증 후보. 실제 정식 인증은 아직 실행하지 않았다.
