# 구현 준비 검토 — 계획 단계

> 초기 계획·검토 기록이다. 현행 상태는 [연구 작업 목록](../tasks.md)과 [코딩 테스트 작업 목록](../../002-coding-test/tasks.md)을 따른다.

## 판정

구현 시작 준비 완료. 연구 결과·공통 구현·실제 팀원 구현·본 실험 완료 판정이 아니다. 다음 실행 작업은 tasks.md T001이며 T001~T021이 공통 평가 MVP다.

초기 계획을 작성할 때 별도 기능 브랜치를 만들지 않았다. setup_plan.py의 논리 식별자는 001-network-protection-study다. 프로젝트 헌법 파일과 확장 훅 설정은 없으며 없는 헌법을 만들어 통과시키지 않았다. 명세 및 사용자 정정을 설계 게이트로 적용한다.

## 설계 준비 확인

- [x] spec.md의 FR-001~039 및 SC-001~011을 tasks.md에 매핑했다.
- [x] 생성 난수 호출 순서·ID·반올림 대표 좌표·LP 잔차/점수 인증·안전 상한의 설계가 정해졌다 (research.md D-001~004).
- [x] spawn/READY/START/최종 수신·평가 IPC·제한 초과·정리 및 실패 기준이 정해졌다 (D-005).
- [x] 전체 알고리즘 RSS, /proc 관측 방식·목표 간격·측정 불가 처리·별도 평가 메모리 기록이 정해졌다 (D-006).
- [x] 문제 생성 난수와 전략 난수를 분리하고 context의 시드/반복 API를 정했다 (D-007).
- [x] 공통 데이터·정규 JSON·식별자·manifest·CLI·종료 코드·보고 형식을 정했다 (data-model.md 운영 계약 v1).
- [x] 별도 contracts/나 팀원 인계 문서를 만들지 않고 세 클래스 docstring/주석만 갱신했다.
- [x] 구현 후 검증 명령·실패 기대값·정식 배포/최종 제출 관문을 quickstart.md에 구분했다.
- [x] 모든 구현 작업은 미완료 상태이며 완료 표시로 과장하지 않았다.

## 실제 수행한 계획/골격 검사

- setup_plan.py --json: 기존 계획 보존 및 FEATURE_SPEC/IMPL_PLAN/FEATURE_DIR/논리 BRANCH 경로 확인.
- setup_tasks.py --json: 기존 작업 목록을 새 설계 기준선에 동기화할 템플릿/문서 확인.
- check_prerequisites.py --json --require-spec --require-tasks --include-tasks: 필수 산출물 조회 성공.
- py_compile: 세 클래스 파일 구문 검사 성공.
- import·AST·solve 서명·NotImplementedError 검사: 세 파일 모두 통과. 알고리즘 본문 대리 작성 없음.
- 요구사항/작업 번호 검사: FR 39, SC 11, 작업 60개. 중복/누락 번호 없음, 50개 요구사항/성공 기준 모두 작업 매핑 보유. 이는 추적 완전성이지 기능 시험 통과율이 아니다.
- 작업별 Story 분류: US1 12, US2 8, US3 15, US4 12개. 나머지는 공통 기반/교차 검수다.
- 작업 체크박스·Story 라벨·대상 경로 검사 통과, 요구사항 매핑에서 고립된 작업 0개. 문서의 단계/순서 의존성을 명시적으로 옮긴 60노드 모델은 순환 없음이다. 이는 자연어 의존성 전체에 대한 자동 증명은 아니며 외부 운영 승인 노드는 제외했다.
- 요구사항 품질 체크리스트는 사용자 결정(A) 반영 및 재검토로 14/16에서 16/16 항목 충족으로 변경했다. 필수 기술 제약은 명세에 보존하고 불필요한 내부 구현 세부사항은 설계 문서로 분리하는 기준을 적용했다. 실제 시험 통과율이나 구현 착수 승인이 아니다.
- 독립 읽기 전용 검토의 생성 호출/수치 경계·RSS/IPC/시드 API 누락 권고를 D-001~008에 대조 반영했다.
- Markdown 상대 링크·코드 펜스 검사 통과. 신규 공통 구현 패키지는 생성하지 않았다.

## 구현 때 반드시 닫아야 할 검증 게이트

| 게이트 | 현재 상태 | 실제 통과 근거 |
|---|---|---|
| 환경·단일 스레드 | 미실행 | T002~003 실제 설치/HiGHS/환경 기록 |
| 수치 정책 | 미실행 | T012/T018 실제 LP, 정확 유리수 인증, midpoint 및 모호성 실패 |
| 공통 평가·생성 | 미실행 | T021 수작업 오라클·재현성·저장 검증 |
| 정확 탐색 | 미실행 | T028 소형 완료 일치 및 T023 중단 시험 |
| 시간/RSS·계약 | 미실행 | T044 실제 프로세스·통신·계측 시험 |
| 노트북·초기 인계 | 미실행 | T052/T058/T059 실제 새 커널/회귀/재현 |

LP 인증의 성능·복원 성공률과 OS 감시의 안정성은 설계 문서만으로 확인할 수 없다. 실패하면 배포/공식 실행 관문을 닫고 정책 변경을 버전과 case_id에 반영한다. 10ms 표본 목표는 연속적인 하드 메모리 제한 보장이 아니다.

## 구현 시작을 막지 않는 외부 운영 관문

- 사용자가 정할 소형 크기·문제 생성 시드 수/목록.
- 실제 장비에서 두 예산 모두 12시간 내 완료한 중·대형 세 크기와 확인 기록.
- 최종 장비/실제 설치 버전·장시간 실행 승인.
- 실제 팀원 세 알고리즘·실명·전략명/버전·관련 연구 설명.
- 무작위 전략의 본 실험 고정 시드 다섯 개.

이 항목들은 T054~T056/T060의 본 실험·최종 제출 관문이다. 임의 값을 채워 설계나 연구가 완료된 것으로 만들지 않는다.
