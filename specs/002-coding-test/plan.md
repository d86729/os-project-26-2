# 구현 계획

1. 표준 입출력 계약을 정의하고, 기존 시나리오 및 채점기에 연결한다.
2. 웹 로그인, 문제 설명, 제출, 직렬 큐, 취소 및 CSV에 같은 계약을 적용한다.
3. WSL에서 사용자·네트워크·파일시스템 격리와 cgroup 자원 제한을 확인한다.
4. 별도 로컬 포트에서 검증한 후 Cloudflare 터널 오리진을 사용하는 테스트 서비스를 교체한다.
5. 웹 결과 화면을 렌더링할 때 저장된 행의 케이스 ID로 검증된 문제은행 참조를 연결한다. 연결 쌍 수와 원정밀도 전달률을 비교해 화면 표시값을 계산한다. 기존 행의 선택 간선과 문제은행의 간선 비용을 이용해 방호 비용을 표시한다. 공식 순위와 로컬 보고 계약은 연구 명세의 사전식 비교를 따른다.
6. 확장 manifest의 크기·시드를 고정하고 공통 잠금으로 완전탐색을 순차 실행한다. 조건별 기록과 쌍 단위 공개 인덱스를 원자적으로 기록한다. 웹과 워커가 공개 인덱스를 읽어 검증된 사례를 사용한다.
