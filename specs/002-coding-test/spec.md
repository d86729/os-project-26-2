# 팀원용 통신망 방호 코딩 테스트

**Feature ID**: `002-coding-test`

**상태**: 표준 입출력 채점과 공개 문제은행 구현. 검증 범위와 이력은 [작업 목록](tasks.md)에 기록한다.

11월 18일 개발 결정에 따라 웹과 로컬 CLI는 표준 입출력을 사용하는 Python 프로그램을 제출받는다. 합성망, 사전식 공식 점수, 완전탐색 참조, 연구 집계와 전략별 책임은 [연구 명세](../001-network-protection-study/spec.md)를 따른다.

## 사용자 시나리오

1. 팀원이 본인 계정으로 로그인해 문제 본문을 읽고 고정 사례의 입력과 참조를 내려받는다.
2. 팀원이 소스와 사례 및 실행 한도를 제출하고, 직렬로 처리되는 자기 제출의 상태를 확인하거나 취소한다.
3. 팀원이 제출 점수와 인증 완전탐색 결과를 비교하고 CSV를 내려받는다. 연구자는 같은 문제와 방호안에서 로컬과 웹의 공식 점수를 대조한다.

## 요구사항

- **FR-001**. `member1`, `member2`, `member3`로 로그인한다. 계정별 선택 내역, 제출 결과, CSV와 취소 권한을 분리한다. 계정당 대기 또는 실행 중인 제출은 한 건이다.
- **FR-002**. 문제 본문은 줄별 입력 형식, 출력 검증, 예제, 자원 제한과 점수 순서를 설명한다. 표준 입력의 노드 구역은 N줄의 `x y`로 구성한다. 간선과 수요의 끝점은 이 구역에서 0부터 센 행 번호를 참조한다. 한 개의 Python 소스를 붙여 넣거나 파일로 제출한다. 소스는 최대 128KiB이며 stdout과 stderr의 합은 최대 64KiB다. stdout은 ASCII로 선택 개수와 오름차순의 중복 없는 간선 번호를 출력한다. 채점기는 비용 합이 예산 이내인지 검사한다. 종료 코드 75는 미구현으로 기록한다.
- **FR-003**. 팀원은 공개 사례의 stdin 텍스트와 최적 참조가 포함된 번들 JSON을 내려받을 수 있다. 사례는 직접 선택하거나 원하는 개수만큼 비복원 무작위 선택한다. 선택한 사례와 한도를 제출 시 고정한다. 각 제출은 사례당 1회 실행하며, 반복 실행이나 시드 고정을 강제하지 않는다.
- **FR-004**. 모든 제출은 직렬로 채점한다. 웹·로컬·문제은행 생성에서 같은 상태 디렉터리를 사용하면 파일 잠금을 공유한다. stdin에는 개수·예산·기지 좌표·통신선·수요·공격 좌표와 피해 선만 전달한다. 예산 비율·문제 시드·전략 시드와 줄 순서로 식별되는 번호는 입력에서 제외한다. 공통 평가기는 정상 종료한 프로그램의 유효한 stdout을 기존 점수 기준으로 채점한다.
- **FR-005**. 로컬은 실행당 300초와 메모리 6,000,000,000바이트로 실행한다. 웹에서는 실행당 1~300초 및 256~6000MB(십진 단위)를 고른다. 두 경로 모두 제출과 자손에 CPU 1개 분량 및 메모리 한도를 적용한다. 제출 실행을 서비스와 격리하고 시간·출력 제한이나 취소 시 자손까지 종료한다. 제출 종료 후 공식 재채점은 별도다.
- **FR-006**. 본인 제출의 선택 사례와 진행 상태, 실행별 적용 한도 및 기록한 결과를 조회하고 결과 행을 CSV로 내려받을 수 있다. 비정상 종료·취소·시간 또는 메모리 초과·출력 오류·공식 채점 실패의 점수는 비워 둔다. 대기 중 취소한 제출은 선택 목록과 제출 상태를 보존한다. 워커가 중단되면 이미 저장한 행을 유지하고 다음 워커에서 남은 실행 중 제출을 중단 또는 취소로 마감한다.
- **FR-007**. 웹 표는 각 점수의 제출안, 동일 사례의 완전탐색 최적 참조, 최적해에서 제출안을 뺀 격차를 표시한다. 정상 행은 연결 쌍 수가 다를 때도 전달률 격차를 부호 있는 %p로 표시한다. 공식 점수 순서는 연결 쌍 수, 전달률이며 연구 보고서와 웹 CSV의 전달 점수 격차는 연결 쌍이 같을 때 정의한다.
- **FR-008**. 웹 결과 표는 노드 수, 예산 비율, 문제 생성 시드, 한국어 상태와 초 단위 실행 시간을 표시한다. 전략 시드는 사용하지 않는다. 시간은 소수 셋째 자리까지 표시하고 방호 간선과 사용 비용은 행 상세에 표시한다.
- **FR-009**. 공개 문제은행은 고정 크기·시드 목록의 합성 그래프를 하나의 인덱스로 제공한다. 그래프별 20%·40% 예산에서 각각 준비·탐색·종료 합계가 10,800초 미만이고 인증 완전탐색을 마친 경우 두 사례를 함께 공개한다. 미완료 및 제외 조건은 연구 기록으로 보존한다.

## 수락 기준

- **SC-001**. 본인 제출의 기존 행과 새 행에 같은 사례의 최적 참조를 표시한다. 연결 쌍 수가 적고 전달률이 더 높은 완료 행에는 양의 연결 쌍 격차와 음의 전달률 격차가 보인다.
- **SC-002**. 실행 실패 및 초과 행에는 상태와 사례가 보이고 공식 점수와 격차는 비어 있다. 대기 취소는 제출 상태와 선택 목록에서 확인할 수 있다.
- **SC-003**. 인증된 사례를 하나의 목록에서 선택하고 기존 이름과 사례 ID로 입력·참조를 다운로드할 수 있다. 한 예산만 완료된 그래프는 공개되지 않는다.
- **SC-004**. 세 계정은 본인 제출만 열람·취소·다운로드할 수 있다. 직접·무작위 선택 결과와 자원 한도가 제출에 고정된다.
- **SC-005**. 동일 사례와 동일 방호안을 정상 채점한 웹·로컬의 공식 평가값이 같다. 취소와 한도 초과는 점수 없이 기록한다.
- **SC-006**. 배포 시 기존 터널 오리진인 `127.0.0.1:18080`에서 로그인 페이지를 제공한다.
- **SC-007**. 같은 사례를 웹에서 내려받거나 로컬에서 생성하면 동일한 입력을 얻는다. 두 입력의 노드 N줄에는 좌표가 두 개씩 있고, 간선과 수요의 끝점은 해당 좌표 행을 참조한다.
- **SC-008**. 입력의 둘째 줄에는 예산만 있고, 간선·수요·공격 후보의 번호는 줄 순서로 정해진다. 전략 시드·문제 시드·예산 비율은 stdin에 없다. 변경 전후 동일한 방호안의 점수와 저장된 인증 최적 참조가 일치한다.
