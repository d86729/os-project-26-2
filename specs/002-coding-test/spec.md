# 팀원용 통신망 방호 코딩 테스트

11월 18일 개발 문서와 사용자 승인에 따라 웹과 로컬 CLI의 제출 계약을 Python 프로그램의 표준 입출력으로 변경한다. 기존 합성망, 점수 순서, 검증된 완전탐색 참조와 반복 규칙은 기존 연구 명세를 따른다.

- FR-001. 세 팀원 계정으로 로그인한다. 계정별 제출과 결과 및 취소 권한을 분리한다.
- FR-002. 입력 전체의 줄별 형식, 출력 검증, 예제, 자원 제한과 점수 계산을 문제 본문에 명시한다. 팀원은 소스를 붙여 넣거나 Python 파일로 제출한다.
- FR-003. 팀원은 저장 시나리오의 입력과 완전탐색 참조를 내려받을 수 있다. 직접 지정 또는 원하는 개수의 비복원 무작위 선택을 지원한다. 고른 조건은 제출과 함께 고정한다.
- FR-004. 모든 제출은 직렬로 채점한다. 각 실행은 초기 상태에서 시작하고 표준 입력에는 시나리오와 예산, 평가에 필요한 입력만 제공한다. 정상 종료한 프로그램의 표준 출력 방호안은 공통 평가기로 채점한다.
- FR-005. 로컬 채점은 시나리오별 300초와 메모리 6,000,000,000바이트로 고정한다. 웹에서는 팀원이 1~300초 및 256~6000MB(십진 단위)를 선택한다. 두 경로 모두 CPU 1개 분량을 적용한다. 제출 코드는 웹과 격리하고, 제한 또는 취소 시 자손 프로세스까지 종료한다.
- FR-006. 본인 제출에서 실행 상태, 적용한 자원 한도, 성적 및 완전탐색 격차를 볼 수 있고 채점 행을 CSV로 내려받을 수 있다. 완료하지 못한 행에는 공식 점수를 두지 않는다.
- FR-007. 웹 결과 표는 각 시나리오의 1순위 연결 쌍 수와 2순위 전달률에 대해 제출안, 완전탐색 최적해, 그리고 최적해에서 제출안을 뺀 격차를 나란히 표시한다. 정상 채점 행은 연결 쌍 수가 다를 때도 전달률 격차를 부호와 함께 표시한다. 공식 순위는 연결 쌍 수를 우선한다.
- FR-008. 웹 결과 표는 노드 수, 예산 비율, 문제 생성 시드, 전략 시드와 한국어 상태를 구분해 표시한다. 실행 시간은 소수 셋째 자리까지 표시하고, 방호 간선과 사용 비용은 행 상세에 표시한다.
- FR-009. 확장 문제은행은 미리 고정한 크기별 시드의 합성 그래프를 사용한다. 각 그래프의 20%·40% 예산에서 각각 10800초 안에 인증 완전탐색을 완료해야 두 사례를 웹에 공개한다. 실패·시간 초과 사례도 연구 기록에 남긴다.

## 수락 기준

세 계정은 각자 제출과 결과에만 접근한다. 같은 시나리오와 소스로 웹과 로컬 채점에서 같은 공식 점수를 재현할 수 있다. 선택한 모든 조건의 실행 상태는 보존된다. 취소한 실행과 한도를 초과한 실행은 정상 점수를 얻지 않는다. 승인된 문제은행의 검증 참조를 재사용하고, 운영 서버는 기존 터널의 로컬 18080 포트에서 동작한다.

- SC-001. 기존 제출과 새 제출에서 같은 시나리오의 최적 참조를 표시한다. 연결 쌍 수가 더 적고 전달률이 더 높은 제출도 두 격차를 각각 표시하며, 전달률 격차는 음수 %p로 표시한다.
- SC-002. 미완료 행에도 상태와 시나리오가 보인다. 미완료 행에는 제출 점수와 격차가 표시되지 않는다.

- SC-003. 기존 사례와 인증된 확장 사례를 웹에서 선택하고 내려받을 수 있다. 하나의 예산만 완료된 그래프는 두 사례 모두 공개하지 않는다.
